### 3.2 假设 #4：`script[data-pjax]` 重执行等价 → **通过（映射规则 = `data-astro-rerun`，但有两个前提）**

执行次数实测（layout 全局 `script[data-pjax][data-astro-rerun]` 每次执行 `window.__pjaxRunTotal++`）：

```
首屏后         runTotal = 1（路径序列 ["/"]）
导航 1 → /page2/  runTotal = 2（路径序列 ["/","/page2/"]）
导航 2 → /       runTotal = 3
导航 3 → pjax.loadUrl  /page2/  runTotal = 4
```

四段断言原文：

```
PASS | data-pjax（全局）导航 1 后执行次数 = 2 | 2
PASS | data-pjax 执行路径序列 = ["/", "/page2/"] | ["/","/page2/"]
PASS | 旧页脚本（首页）未重复执行：__homeScriptRuns=1 | 1
PASS | 新页脚本（第二页）首次进入执行一次：__page2ScriptRuns=1 | 1
PASS | 页级 data-pjax 脚本首次进入执行一次：__page2PjaxRuns=1 | 1
PASS | 导航 2：页级 data-pjax 未跨页重复执行：__page2PjaxRuns=1 | 1
PASS | 第二次进入第二页：data-astro-rerun 让页级 pjax 脚本再执行一次（=2） | 2
PASS | 第二次进入第二页：无 rerun 的页面脚本仍按内容去重（=1） | 1
PASS | astro:before-swap / after-swap / page-load 各触发一次
       [{"name":"astro:before-swap","path":"/","at":2426},   ← 注意 before-swap 时 location 还是旧页
        {"name":"astro:after-swap","path":"/page2/","at":2431},
        {"name":"astro:page-load","path":"/page2/","at":2435}]
```

结论与前提：

- **每次导航恰好执行一次**：`data-astro-rerun` 是等价开关。**没有它，Astro 会按脚本原文/URL 跨导航去重，只在第一次执行**（实测：page2 页级脚本第二次进入仍为 1；首页页面级脚本从首页离开再回来仍为 1）。
- 所以 Phase 4 的映射规则必须写成：**上游每一个 `script[data-pjax]` → 增加 `data-astro-rerun`**；忘了这个标记 = 静默只跑一次，这是最容易踩的坑。
- 旧页脚本不重复执行 ✅（旧 body 已随 swap 移除，且 Astro 的 `data-astro-exec` 按脚本内容/URL 去重生效）。
- `astro:before-swap` 触发时 `location.pathname` 还是旧路径——Phase 4 若在 before-swap 里用 `location` 判断目标页会踩坑，应该用事件对象的 `to`，或在 `after-swap/page-load` 里读。

## 4. 额外发现（Phase 4 必须处理 / 值得知道）

### 4.1 `html[data-theme]` 是上游 CSS 的运行时契约（否则 `#web_bg` 背景直接失效）

上游把 `--anzhiyu-*` 变量只定义在 `[data-theme="light"]` / `[data-theme="dark"]` 下（产物 CSS 原文）：

```css
[data-theme="light"] {
  --anzhiyu-background: #f7f9fe;
  ...
}
[data-theme="dark"] {
  --anzhiyu-background: #18171d;
  ...
}
```

迭代中第一版没有给 `<html>` 写 `data-theme`，实测 `#web_bg` 的 `backgroundColor = rgba(0, 0, 0, 0)`（`background: var(--anzhiyu-background)` 因变量未定义整条声明失效）；补上 `data-theme="light"` 后变为 `rgb(247, 249, 254)`。

→ **Phase 4 必须补一个首屏前执行的 theme bootstrap**（localStorage / `prefers-color-scheme` → 写 `document.documentElement.dataset.theme`），否则整套 `--anzhiyu-*` 变量在首屏和导航后都可能缺失。垂直切片里先静态写死 `data-theme="light"`。

### 4.2 重执行会给 `document` 叠加监听（浏览器不报错，只能靠计数看）

layout 的全局 `script[data-pjax][data-astro-rerun]` 里模拟了上游常见写法“每次执行都 `document.addEventListener('pjax:probe', ...)`”。4 次执行后 dispatch 一次：

```
[INFO] 重复监听累加：dispatch 一次 pjax:probe 命中数 = 4
```

浏览器不会为此报 console error（“无重复监听报错”这一项在字面上是“没有错误”，但**语义上监听确实在泄漏**）。→ Phase 4 的 shim 必须提供**幂等初始化**：要么上游脚本内自查 guard（`if (window.__xBound) return`），要么把 `pjax:complete` 逻辑集中到唯一常驻模块（首次加载注册一次，之后每次 page-load 分发）。

### 4.3 上游「非 data-pjax 脚本在 pjax 后不执行」的语义，Astro 默认不保证

Astro 的 `runScripts()` 在每次 swap 后遍历新文档里的所有 `script`：没见过的脚本会执行，见过且没 `data-astro-rerun` 的跳过。实测：page2 独有的普通内联脚本首次进入执行 1 次、二次进入不再执行；首页页面级脚本离开再回来也不执行。

而上游 pjax 的语义是「只重执行 `script[data-pjax]`」。**两者对“页面独有但没标 data-pjax 的脚本”行为不同**：上游首次 pjax 进 page2 不执行，Astro 会执行一次。→ Phase 4 需要逐个审计上游页面级 script：
- 语义是“每次导航都跑” → `data-astro-rerun`
- 语义是“只在整页加载时跑” → 目前等价手段是进产物时预置 `data-astro-exec` 属性（`runScripts` 会跳过），或把脚本收敛进 layout 常驻模块，由 `astro:page-load` 统一分发。**这条建议作为 Phase 4 的一个显式验证项**（本切片未覆盖该分支行为，只验了 dedupe 事实）。

### 4.4 像素验收要防 DPR 设备像素吸附 + 上游 media query 分支

- 本机 agent 浏览器 DPR=1.5：CSS 5px 边框 computed 是 `4.66667px`，1px 是 `0.66667px`。**视觉验收断言写死 `5px` 会假失败**，应使用 `floor(css*dpr)/dpr` 复核，或断言比例。
- 视口 1258 ≥ 1201 时上游 `article_double_row: true` 走「双列卡片（column + width:49%）」；≤1200 才是「横排卡片（row + height:18em）」。视觉基线必须按视口分支写，否则会把配置行为当回归。

### 4.5 `astro preview` 是单例

本机已有 preview 在跑时，再起第二个（即使换端口）会直接失败：

```
Another astro preview server is already running.
  URL:  http://127.0.0.1:4399
Run `astro preview stop` to stop it, or use `astro preview --force` to replace it.
```

→ CI/并行验证时注意先停旧 preview 或用 `--force`（Playwright 脚本首次试跑就是因此没起来，后已修正执行顺序）。

### 6.2 失败/退路矩阵（本次没有触发，但 Phase 4 要留）

| 环节 | 若坏 | 退路 |
|---|---|---|
| 全局背景/侧栏持久化 | 整 body 替换导致背景闪断 | `transition:persist` 已实测可用；再不行用独立 fixed 层 + 每次 after-swap 重挂 |
| `script[data-pjax]` | 脚本不重执行/重复执行 | 加 `data-astro-rerun`；仍不行则 `pjax:complete` 由常驻 shim 统一调用 refreshFn 注册表 |

### 6.3 Phase 4 实施建议（可直接映射到 P4 任务）

1. **`pjax-bridge` 常驻模块（Phase 4 第一优先）**
   - `window.pjax.loadUrl(url, {history})` → `navigate()`（`history:false` → `replace`）
   - `astro:page-load` → 补发 `pjax:complete`（只注册一次）
   - 提供 `window.refreshFn` 注册表：上游 `pjax:complete` 时重跑的函数在这里注册，**由 bridge 统一调用**，避免整段脚本重执行
   - 建议 `pjax` shim 增加 `pjax.loadUrl` 的 `{container, fragment}` 参数兼容（上游模板里可能出现，Phase 4 审计后按需）
2. **上游脚本迁移规范（P4 脚本层）**
   - `script[data-pjax]` → 首选改成「注册到 refreshFn / 监听 pjax:complete 的幂等函数」；纯 IIFE 无法改造时加 `data-astro-rerun`
   - 页面独有且只在整页加载时执行的脚本：进产物时预置 `data-astro-exec`（Phase 4 先写一条验证用例确认该机制在 Astro 7 下行为符合预期）
   - 所有 `document.addEventListener` 都要有 guard 或集中到 bridge
3. **主题 bootstrap（P4 全局初始化）**：首屏前设置 `html[data-theme]`（localStorage → `prefers-color-scheme` → 默认 light），同步处理暗色模式切换（只改属性，不重建节点）。
4. **持久层规范（P4 全局元素）**：`#web_bg`、侧边栏、音乐播放器、右下角菜单等统一 `transition:persist`；跨组件渲染的持久元素显式写 `transition:persist="稳定id"`；persist 元素内部不要依赖“导航时重新初始化”的副作用。
5. **音乐播放器（P4-7）**：走 persist 方案；播放列表/当前曲目/进度放模块单例 + localStorage，整页刷新可恢复。
6. **视觉验收测试规范（P6/P7 前置）**：断言用 DPR 公式 / 比例 / 范围；`article_double_row` 的 ≥1201px 双列分支要进基线；截图比对前固定视口与 DPR。
7. **CI 测试入口**：`pnpm --filter blog test:slice` 跑 `tests/vertical-slice.mjs`（Playwright）。本机沙箱跑不了；CI 是 Linux 容器，Playwright 正常。页内 harness 作为本机/手动回归的补充，保留但不再作为主要手段。

## 8. 结论（最后一段）

八项技术假设里剩下的五项，这次全部放进真实浏览器跑完了：#3 全局背景 **通过**——导航后 `#web_bg` 仍是同一个 DOM 节点，12 项 computed style 与导航前逐项一致；#4 `script[data-pjax]` 重执行 **通过**——用 `data-astro-rerun` 映射后，4 次页面状态里全局脚本执行次数精确为 1→2→3→4，旧页脚本不重复执行，console error 0 且 `pjax.loadUrl` shim 路径同样成立，但必须知道「不加 rerun 会静默只跑一次」和「重执行会累积 document 监听」两个前提；#5 样式命中 **通过**——`.note`、`.note.blue`、`.note.red.simple`、`.recent-post-item`、`#web_bg` 的 computed style 全部命中上游 Stylus 规则值；#6 pug 风格 HTML **通过**——两页构建绿、void 标签不闭合原样进产物且浏览器正确解析；#8 音乐播放器 **通过**——persist 的播放器容器与 `<audio>` 跨 4 次导航保持同一节点、`paused=false` 且 `currentTime` 单调递增，音频不中断。额外还确认了导航过程 document 请求为 0、console/pageerror 全 0，并顺带暴露了三个 Phase 4 必须处理的点：`html[data-theme]` 的运行时契约（否则 `#web_bg` 背景直接透明）、重执行脚本的监听幂等、以及像素验收要防 DPR 设备像素吸附与上游 media query 分支。因此 **Phase 4 可以按「ClientRouter + pjax shim」原方案推进**，把上述 3 个前提作为 P4 的显式验收项即可；音乐播放器退路（独立持久层）经实测**不需要启用**。唯一需要说明的是本机 Playwright 被 DSH 沙箱阻断（证据完整、非代码问题），本次真浏览器验证由 Edge + 页内 harness 完成，Playwright 脚本作为 CI 入口保留。
